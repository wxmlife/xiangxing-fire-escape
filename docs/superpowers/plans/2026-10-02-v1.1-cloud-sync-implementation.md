# 巷行 V1.1 可选云同步、团队共享与服务端排行 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在完整保留游客本地模式的前提下，交付可选的 CloudBase PostgreSQL（上海）账号、跨设备不可变版本同步、团队共享、私有图片、服务端重算排行榜以及可恢复删除能力。

**Architecture:** 浏览器只在用户主动使用“跨设备同步/邀请成员/服务端校验排行”时懒加载自托管的 CloudBase JS SDK；未配置、未登录或离线时继续使用本地核心计划的 IndexedDB、规划器和排行榜。客户端通过稳定的 `CloudPort`、本地 outbox 与幂等云函数同步不可变 `SceneRevision`/`PlanRun`，简单读取受 PostgreSQL `GRANT + RLS` 双层保护，敏感写入、团队管理、分享和排行榜校验均由认证云函数完成；图片进入私有 PG Bucket 前再次裁剪重编码，分享只发放短时签名地址。

**Tech Stack:** 原生 ES modules、IndexedDB、Web Crypto、`@cloudbase/js-sdk@3.10.1`（PG 模式）、`tencentcloud-sdk-nodejs-tcb@4.1.321`（仅服务端管理 API）、CloudBase Node.js Event SCF、CloudBase PostgreSQL/RLS、PG 云存储、Node.js `node:test`、PostgreSQL 15 CI service、Playwright Chromium、`@cloudbase/cli@3.8.5`。

**Spec:** `docs/superpowers/specs/2026-10-02-v1.1-realtime-recognition-routing-design.md`

## Global Constraints

- 游客本地识别、修正、规划、历史、备份和本地排行榜必须始终可用；应用启动、打开登录面板或云端故障均不得触发上传或阻塞本地功能。
- 云同步是逐场景显式启用；默认不上传实时帧，只上传用户明确保存并选择同步的修订、运行和快照。
- CloudBase 环境固定为 PG 模式、地域 `ap-shanghai`；前端只能包含环境 ID 与 Publishable Key，API Key、`service_role`、腾讯云 SecretId/SecretKey 和管理员数据库凭证不得进入 `dist/`、Git 或浏览器。
- 浏览器使用 `@cloudbase/js-sdk` v3 的 `app.auth`、`app.rdb()`、`app.callFunction(...)` 与 `app.storage.from(bucketId)`；不得混用旧版 `app.auth()` 或文档型数据库 API。
- `SceneRevision.schemaVersion === '1.1'`，本地 `sceneId/revisionId/runId` 原样成为云端身份键；同 `sequenceNo` 的离线分支全部保留，绝不按序号或最后写入覆盖。
- `scene_versions`、`scene_objects`、`plan_runs`、`route_results`、`audit_events` 和同步回执均为追加写；身份键已存在且 payload hash 不同必须拒绝为 `IDENTITY_HASH_MISMATCH`。
- 浏览器持久化与线上 JSON 的时间字段统一为 UTC RFC 3339 字符串，PostgreSQL 使用 `timestamptz`；软删除、分享过期、排行记录和审计的权威时间只取服务端时钟。
- 团队角色固定为 `owner | editor | viewer`：owner 管理成员、分享与删除；editor 可追加场景版本与运行；viewer 只能读取。角色判断必须由服务端/RLS执行，不信任客户端字段。
- 所有业务表启用 RLS 并显式配置表级 GRANT；`anon` 默认不可读业务表，`authenticated` 只见所属 workspace，`service_role` 只存在服务端。
- CloudBase 网关使用 OPA/Rego v1 最小权限策略并显式 `deny`：认证用户只能调用本文列出的函数与场景私有存储上传/签名 API；游客只能调用独立的 `xiangxing-read-share` 只读函数，不能调用同步、管理、校验、隐私函数或直接列举存储。OPA 替代旧的 `FunctionsHttpApiAllow`/`StoragesHttpApiAllow` 粗粒度策略，二者不得被宽泛附加。
- 全部云函数均部署为 `type:'Event'`、handler `index.main`，`public` 省略或为 `false`；浏览器只通过 `app.callFunction` 调用，匿名分享权限只来自精确 OPA 规则，清理函数只接受计划触发/service 调用。
- 所有 `SECURITY DEFINER` 函数必须显式校验请求角色/用户、固定 `search_path = public, private, pg_temp`，且不得仅依赖 `GRANT EXECUTE` 作为安全边界。
- PG Bucket `xiangxing-scenes` 与 `xiangxing-exports` 均保持私有；分享页不得调用 `getPublicUrl` 或列目录，只能取得默认 300 秒的签名地址。
- 云端默认只上传裁剪、俯视校正、重新编码并已移除 EXIF/GPS 的沙盘区域与缩略图；“完整原图”也只上传移除元数据后的整幅重编码图（不保留原始字节），且需要单独勾选并保存 `explicitConsentAt`。
- 照片仍遵守 20 MB、2400 万解码像素限制；上传对象 MIME 仅允许 `image/webp` 或 `image/png`，对象内容 hash 使用 SHA-256 小写十六进制。
- 只读分享令牌使用 32 个随机字节（256 位）base64url 编码，数据库只存 SHA-256；默认 7 天过期，可立即撤销，URL 令牌放在 `#share=` fragment 中。
- 云排行榜只收录服务端以已保存输入重算一致、`reviewCompleted === true`、`allEvacuated === true`、`optimalityStatus === 'proven'` 的运行；标签固定为“服务端校验”，不得称为现实安全认证。
- 静态榜键固定为 `(sceneId,startRevisionId,plannerVersion,simulationProfileVersion)`；动态回放额外包含 `scenarioScriptHash`，不同键不混排。
- 场景、图片和账号数据删除先立即失去读取/分享权限，再进入 7 天可恢复软删除；到期才清除数据库对象与存储对象。
- 微信登录、短信登录、真实跨设备、真实分享撤销和真实云排行属于外部激活门禁；缺少 CloudBase 环境、微信资质、短信服务或安全域名时，界面明确显示“云同步尚未配置”。
- GitHub Pages 继续发布 `dist/`；CloudBase SDK 必须由锁定版本构建到 `dist/vendor/` 自托管，CSP 不允许远程脚本或用户 HTML。

## Review Focus

- 配置缺失、网络离线、登录过期或云函数失败：本地保存继续成功，outbox 保留且退避重试，不丢数据、不自动上传未选择场景；Task 1、2、7 用禁用端口和离线恢复测试锁定。
- 同一 operation 重放、同一 ID 不同 hash、缺失父版本或两设备同 `sequenceNo`：幂等回执、显式拒绝或保留双分支，绝不静默覆盖；Task 3、7 用 SQL/函数集成测试锁定。
- viewer 越权、枚举对象路径、过期/撤销分享、伪造令牌或分享响应夹带账号信息：一律拒绝且不返回稳定图片 URL、邮箱或手机号；Task 4、8 用 RLS 与分享响应测试锁定。
- 客户端伪造 `allEvacuated`、时间、hash、规则版本或缺少动态 timeline：服务端重算拒绝，失败记录仍可留历史但不进榜；Task 9 用篡改矩阵测试锁定。
- 软删除后立即撤销分享/图片读取，7 天内可恢复，期满数据库与对象均清除；唯一 owner 尚有成员时必须先转移或删除 workspace；Task 10 用假时钟和清理集成测试锁定。
- 网关平台默认放行、旧粗粒度策略或路径前缀混淆不得扩大匿名/认证权限；Task 8 拆分只读分享端点，Task 12 用真实 Rego deny 矩阵和 staging 403 探针锁定。
- 普通有效会话、客户端 reauth 布尔值、会话时间戳或旧 token 不能申请账号删除；Task 10 用服务端 `RecentAuthProofAdapter`、同一绑定身份验证、哈希保存的一次性 proof 与并发事务测试锁定。

## Prerequisite Local/Realtime Interfaces

本计划开始前，本地核心计划必须已经提供并保持下列签名；云端代码只导入，不复制算法或数据模型：

- `dist/core/contracts.mjs`: `createScene(...)`、`createSceneRevision(...)`、`validateSceneRevision(...)`、`createPlanRun(...)`、`createEvacueeResult(...)`。
- `dist/core/photo-input.mjs`/感知流水线：产出 `CandidateRevisionBundle = { revision, imageRecord }`；`revisionId` 由感知前的 `RevisionReservation` 生成并贯穿 worker/pipeline。`ImageRecord = { hash, width, height, mime, boardBlob, thumbnailBlob, normalizedFullOriginalBlob, originalConsentAt }`；默认只含已校正、重编码并移除 EXIF/GPS 的 `boardBlob` 与 `thumbnailBlob`，最后两项为 `null`。只有创建流水线参数 `retainNormalizedFullOriginal === true` 且 `originalConsentAt` 非空时，记录才可含经定向、重编码、去元数据的完整图；该布尔参数本身不是 `ImageRecord` 字段。
- `dist/core/rle.mjs`: `decodeRevisionMasks(masks)`，导入云数据前仍执行最大像素与 RLE 校验。
- `dist/core/lexicographic-routing.mjs`: `planRevision({ revision, profile, plannerVersion, maximumSearchNodes, mode, startState = null }): Promise<PlanningResult>`；`mode` 必填 `preview | formal`，返回的 `candidatesByPerson` 必须原样交给调度器。
- `dist/core/simulation.mjs`: `scheduleSevenEvacuees({ revision, candidatesByPerson, profile, maximumSearchNodes, continuation = null, startState = null }): SchedulingResult`；服务端每次重算只能在一次 planner 调用后调用一次 scheduler，两者收到同一个 `startState`，不得另调 candidate generator、二次调度或重复累加 `currentSimMs`。
- `dist/core/simulation-profile.mjs`: `ESTIMATED_SIMULATION_PROFILE`、`MEASURED_SIMULATION_PROFILE` 与受支持版本查找。
- `dist/core/local-store.mjs`: `openLocalStore(...)` 返回 Task 2 扩展前已有的 scene/revision/run/image/backup API，并提供 `LocalStore.putImage(imageRecord)` 与原子 `LocalStore.putRevisionBundle({ revision, imageRecord })`；`SceneRevision.image` 精确引用同一记录：`{ hash, width, height, thumbnailRef:{ hash, variant:'thumbnail' }, originalRef:{ hash, variant:'board' }, fullOriginalRef: imageRecord.normalizedFullOriginalBlob ? { hash, variant:'normalized-full' } : null }`。这里 `originalRef` 是已清洗、校正的沙盘图，不是相机原始字节。
- `dist/core/leaderboard.mjs`: `leaderboardKey(run)` 与 `isLeaderboardEligible(run)`；云榜必须在此基础上再要求服务端 accepted validation。
- 实时计划持久化的 `PlanRun.revisionTimeline`、`scenarioScriptHash` 及被引用修订必须可由本地 store 枚举。
