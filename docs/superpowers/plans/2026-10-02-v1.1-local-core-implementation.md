# 巷行 V1.1 本地核心 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在保持 GitHub Pages 纯静态部署的前提下，交付无需登录即可完成“照片导入 → 自动候选识别 → 人工复核 → 严格优先级规划 → 七人仿真 → 本地历史与排行榜”的 V1.1 本地核心。

**Architecture:** 将现有 `app.js`/`planner.mjs` 中混合的界面、感知和寻路逻辑拆为版本化的纯函数核心、两个普通 Web Worker、IndexedDB 仓库和薄 UI 控制器。照片上传与后续摄像头“拍摄当前帧”统一经过 `createCandidateRevisionFromImage(...)`，规划只消费冻结的 `SceneRevision`；视觉模型可替换，但 RLE 场景、道路图、词典序规划、仿真和历史格式保持稳定。实时摄像头与云端同步分别由后续计划实现，只依赖本计划锁定的接口。

**Tech Stack:** 原生 ES modules、Canvas 2D/ImageData、Web Worker、IndexedDB、Web Crypto、Node.js `node:test`、`fake-indexeddb`、Playwright Chromium；运行时代码不引入框架或服务端依赖。

**Spec:** `docs/superpowers/specs/2026-10-02-v1.1-realtime-recognition-routing-design.md`

## Global Constraints

- 产品只用于受控教学沙盘和算法演示；页面持续显示“候选结果需人工复核”，不得描述为真实火场认证导航。
- 游客无需登录即可使用照片识别、修正、规划、历史与本地排行榜；云端未配置或离线不得阻塞本计划功能。
- GitHub Pages 继续直接发布 `dist/`；不得在浏览器或仓库中加入管理员密钥，也不得要求 `SharedArrayBuffer` 或跨域隔离头。
- 支持 JPEG、PNG、WebP；单文件不超过 20 MB，解码后不超过 2400 万像素；HEIC/HEIF 只在浏览器原生解码成功时接受。
- `SceneRevision.schemaVersion` 固定为 `'1.1'`；`revisionId`、`runId` 使用全局 ULID，`sequenceNo` 仅用于排序，不能用于覆盖身份。每次识别必须先创建不可变 `RevisionReservation`，其 `revisionId` 贯穿感知请求、候选修订、规划请求与持久化，不允许 Worker 返回后再分配身份。
- 掩膜语义固定为 `0 = road`、`1 = blocked`、`2 = unknown`；降采样时硬障碍优先、未知次之，只有全为高置信道路才可通行。
- 正式规划门槛固定为：恰好 7 个已确认起点、至少 1 个已确认出口、火源状态已确认、全部低置信组件已处理、障碍已复核，且起点/出口不在硬障碍或未知区。
- 规划网格默认 108 列；未测量场景仅显示“网格”“沙盘宽度百分比”和“模拟秒”，不得显示伪造的厘米、米或真实逃生时间。
- `sim-1.1-estimated` 固定采用：有效人员宽度比 `0.046`、正交步 `350 ms`、对角倍率 `Math.SQRT2`、时隙 `250 ms`、出口服务 `1000 ms`、开放堵塞阈值 `0.15`、最低限速倍率 `0.35`、每人最多 8 条候选、实时搜索上限 20000 节点。
- `sim-1.1-measured` 固定采用：模拟身体宽 `0.55 m`、双侧各 `0.15 m` 安全余量、最低净宽 `0.85 m`、无堵塞速度 `1.0 m/s`；其他候选、堵塞、出口和搜索预算与估算模式一致。
- 火源半径必须全部有限并满足 `0 < hardRadius < riskRadius <= Math.SQRT2`；路线火源安全余量必须扣除火源位置不确定度与配准位置误差。
- 路线优先级是不可抵消的严格顺序：硬约束 → 火源最小安全余量 → 累计暴露 → 最严重堵塞率 → 长度加权平均堵塞率 → 全员撤离时间 → 距离 → 稳定哈希。
- 火源余量、暴露量、最大堵塞和平均堵塞四个高层指标都必须先进入 `PLANNER_PROFILE_V1_1` 定义的确定性容差桶；ETA/距离只能打破四个桶完全相同的平局，不能直接用 `1e-6` 舍入后的原始高层浮点值排序。
- 每次规划必须显式选择 `mode: 'preview' | 'formal'`：预览可消费未完成复核的候选修订，但永远不可保存为正式运行、不可排行；正式模式必须先通过全部复核门槛。
- `UNKNOWN`、火源硬禁行区、净宽下界不足、落入障碍的起点/出口都直接受阻；不得吸附到墙体另一侧，也不得用较短距离抵消风险。
- 动态仿真的权威位置只能是 `SimulationSnapshot.evacuees[].currentPosition`（归一化沙盘坐标），权威时间只能是 `SimulationSnapshot.simTimeMs`；`currentGridCell` 仅供渲染/缓存，规划和续跑不得把它当作位置真值。
- 正式排行榜只收录 `reviewCompleted === true`、`allEvacuated === true`、`optimalityStatus === 'proven'` 的完成运行；不同场景修订、规划器版本和仿真参数版本绝不混排。
- 图片采用两阶段生命周期：先只解码为定向后的内存像素，完成四角校正后再把沙盘区域裁切、重新编码并移除 EXIF/GPS。默认持久化校正沙盘图和缩略图；只有用户明确勾选保留完整图并记录同意时间时，才保存同样经过定向、重新编码和去元数据的完整图。达到存储配额估计值 80% 后停止保存新完整图，只保留缩略图和掩膜差分。
- 内存实时修订上限为 120；单场景自动事件检查点上限为 200，基准、人工确认版和正式运行引用版不可自动删除。
- 390 px 宽视口不得产生页面横向滚动；地图编辑必须提供显式“编辑锁定/页面滚动”切换。
- 识别验收数据不足 30 张、未完成分层准确率门禁时，不得宣称达到 95%/98% 正式指标；自动结果始终为待复核候选。

## Review Focus

- 损坏、伪造 MIME、超过 20 MB、超过 2400 万像素或浏览器不支持的 HEIC：在启动识别前给出可操作错误、释放位图/对象 URL，并可立即重新选择图片；Task 2 用解码失败与资源释放测试锁定。
- 恶意或损坏的 RLE（负长度、总长不符、未知格值、宣称巨大尺寸）：必须拒绝，不能分配无界内存；Task 1 用损坏备份输入测试锁定。
- 两台离线设备产生相同 `sequenceNo` 或导入同一场景的两个分支：全局修订 ID、父链和两个分支全部保留；Task 9 用 IndexedDB 导入冲突测试锁定。
- 起点/出口落入硬障碍、未知区或火源禁行圈：返回明确受阻原因且路径为空，绝不“最近自由格”吸附；Task 6 用三个硬约束回归测试锁定。
- Worker 取消、崩溃、识别超过默认 15 秒或旧修订版晚到：旧结果不能覆盖当前修订，超时返回 `WORKER_TIMEOUT`，当前输入仍可重试或转纯手工；Task 8 用预留修订 ID、乱序响应、虚拟计时器、AbortSignal 和 Worker error 测试锁定。

### 版本化核心

- `dist/core/ids.mjs`：单调 ULID 生成器和可注入测试时钟。
